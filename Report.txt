Cameron Wills Report:
The critical service, auth-ticket-daemon (files/service.py), simulates an authentication server similar to a Kerberos KDC. Each cycle, its main thread receives a simulated login request, checks the credentials against salted password hashes, and issues a 128-bit session ticket on success. A separate background thread sends a JSON heartbeat over UDP to the monitor at 127.0.0.1:9999 once per second (T = 1.0 s). Because it runs apart from the authentication loop, slow logins cannot delay heartbeats and trigger false alarms. To model an unpredictable production failure without a fixed crash point, every cycle checks random.random() < 0.08. When this fires, the service logs a fatal segmentation-fault message about a malformed authentication payload, with UTC and local timestamps, the cycle number, and the last heartbeat number sent. It then calls os._exit(1), which ends the whole process at once, including the heartbeat thread. The heartbeats simply stop, so the monitor sees only silence, as it would after a real crash. Each cycle lasts about one second, so the expected uptime is 1/0.08 ≈ 12.5 s. In our test runs, the service crashed after 5 to 30 s, and the monitor raised its alert 3.01 s after the last heartbeat.
